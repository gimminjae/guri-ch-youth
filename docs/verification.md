## 비밀번호 제한 제거·초기 등록 검증 (2026-10-08)

- 화면의 최소·최대 길이 속성, 로그인 API 최대 길이 검사, DB의 해시 생성·로그인 길이 검사, 초기 SQL 생성기의 길이·문자 검사를 제거했다. 공백을 자르거나 문자를 정규화하지 않는다.
- 실제 SQL과 API에서 한 글자, 128자를 넘는 한글 비밀번호, 공백·따옴표·특수문자를 포함한 값으로 변경·로그인했다. 끝 문자가 다른 비밀번호는 거부되며 기존 해시 저장과 시도 횟수 제한은 유지된다.
- `--schema-only` 적용 후 비밀번호가 0건임을 확인하고 `db:seed`에 해당하는 SQL로 세 역할을 등록했다. 반복 실행 시 기존 비밀번호가 보존되며 환경변수 누락은 명시적인 오류가 된다.
- 현재 `.env` 값은 변경하지 않고 `.local/supabase-passwords.sql`을 생성했다. 새 후속 마이그레이션을 먼저 적용한 뒤 초기 등록 SQL을 실행한다.
- 현재 Supabase 연결 도구의 SQL 실행 권한이 거부되어 실제 DB 조회·변경은 수행하지 못했다. SQL Editor에서 적용해야 한다.

## 모바일 우선 화면·행 상세 조회 검증 (2026-10-09)

공통 CSS 모듈에 모바일 여백, 44px 버튼, 16px 입력 글자, 모달 내부 스크롤을 적용했다. 표의 제목·값·배지를 가운데 정렬하고, 전체·그룹별 목록에서 행 클릭과 Enter/Space로 기존 전체 필드 상세 모달을 열도록 연결했다.

- 변경 후 `npm run lint`, `npm run typecheck`, `npm run build` 통과.
- 프로덕션 빌드와 임시 PGlite/API 서버를 Chrome에 연결해 320×568, 360×800, 393×852, 1280×900 뷰포트에서 확인했다. 페이지 너비와 가로 스크롤 너비가 같으며, 넓은 표의 가로 스크롤은 표 영역에 한정된다.
- 모든 `th`·`td`의 실제 `text-align` 값이 `center`임을 확인했다. 단일·다중 선택 배지도 가운데 표시된다.
- 일반 목록과 그룹 내부의 이름 셀 클릭으로 상세가 열리며, 목록에서 숨긴 `기도 응답` 항목과 본문 원문·작성/수정 시각이 표시된다.
- 행에서 Enter/Space, 기존 상세 버튼으로 열기, Escape로 닫기를 확인했다.
- 320px 화면에서 모달은 위아래 12px 여백 안에 있고, 본문만 세로 스크롤된다. 헤더의 닫기 버튼은 본문 스크롤과 분리된다.

## 모바일 목록 가로 스크롤 제거 (2026-10-09 후속)

- 최종 `npm run lint`, `npm run typecheck`, `npm run build` 통과.

## 필드 미사용·다시 사용·삭제 (2026-10-10)

`isActive` 상태, 관리자 전체 필드 조회, 상태 변경과 미사용 필드 영구 삭제를 추가했다. 린트·TypeScript·43개 테스트·프로덕션 빌드가 통과했다. 샌드박스 안의 빌드가 진행되지 않아 해당 빌드만 중단한 뒤 로컬 IPC가 허용되는 환경에서 빌드를 완료했다.

추가 자동 검증:

- 관리자만 전체 필드 조회·상태 변경·삭제 가능. 비인증·구성원·부관리자, 위조 출처, 잘못된 상태 값과 오래된 수정 시각을 API·직접 RPC에서 거부한다. Next.js의 PATCH 라우트 연결과 출처 검사도 확인한다.
- 미사용 값은 상세·목록·그룹·필터·집계·XLSX 응답에서 제외한다. 저장된 첨부파일의 직접 조회·새 업로드도 차단한다.
- 일반 수정과 엑셀 수정 후에도 미사용 값·첨부·목록 표시 선택을 보존하고, 다시 사용하면 값과 기존 설정을 복원한다.
- 필드 상태 변경 후 이전 엑셀 미리보기 확정을 거부한다. 관리자의 순서 저장은 미사용 필드까지 포함한 전체 구성을 검사한다.
- 삭제는 미사용 상태에서만 가능하다. 해당 값과 목록 표시 선택만 제거하며 다른 값과 기도부탁은 유지한다. 관련 기도부탁의 수정 시각을 갱신해 오래된 편집을 거부한다.
- 첨부 삭제 실패 시 큐를 보존하고 재시도한다. 필드 삭제 중 진행 중이던 업로드는 정리 기록을 유지하며, 완료 거부 후 실패 처리·정리로 객체를 제거한다.
- 버전 4 DB를 버전 5로 올릴 때 기존 필드를 사용 중으로 유지하고 자료·세션을 보존한다. 마이그레이션을 재실행해도 미사용 상태를 초기화하지 않는다.

프로덕션 화면과 임시 PGlite/API 서버를 이용한 Chrome 검증:

- 320px·393px에서 관리자 필드 목록·미사용 버튼·다시 사용 버튼·삭제 확인 모달을 확인했다. 페이지와 모달의 가로 스크롤 너비가 화면 내부 너비와 같았다.
- 사용 중인 필드의 삭제 버튼이 비활성화되고, 미사용 전환 후 삭제 확인 모달에 전체 기도부탁의 해당 값·첨부파일 삭제와 복구 불가 안내가 표시된다. 브라우저에서는 취소까지 확인했고 영구 삭제 결과는 위 SQL/API 테스트로 검증했다.
- 미사용 전환 직후 목록 열·그룹 메뉴·집계·작성 폼·상세에서 해당 필드가 사라지고, 다시 사용하면 기존 다중 선택 값이 표시됐다.
- 모든 필드를 미사용으로 전환한 뒤에도 관리 화면에는 전체 필드가 표시되어 다시 사용할 수 있었다.
- 393px에서 표 형태의 목록을 유지하며 가로 스크롤이 없고, 제목·셀의 가운데 정렬과 행 클릭 상세 조회가 유지됐다.
- 별도 Next.js 서버의 실제 HTTP OPTIONS 응답에 PATCH가 포함됐다.

Supabase CLI `db advisors --local --type security --fail-on error`는 로컬 DB(54322) 연결 거부로 실행하지 못했다. 실제 SQL과 공개 DB 역할의 테이블·함수 권한은 PGlite에서 검사했다. 운영 DB의 advisors, 다중 연결 경합, 실제 S3 정리와 모바일 실기기 검증은 포함하지 않는다.

운영 적용용 `.local/supabase-setup.sql`을 `--schema-only --existing-schema`로 생성했다. 초기 비밀번호가 없고 실제 DB에는 자동 적용하지 않는다. 버전 4까지 적용된 DB는 `supabase/migrations/20261009020025_field_lifecycle.sql`만 SQL Editor에서 실행해도 된다.

## 실제 연결 후 남은 확인

1. `.env` 또는 `.env.local`의 Supabase URL·publishable key를 채우고, `db:prepare`로 만든 SQL을 SQL Editor에서 실행한다. `db:check`로 연결을 확인한다.
