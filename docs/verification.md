통합 테스트는 PGlite에 실제 SQL 마이그레이션을 적용하고 앱의 API 핸들러와 `anon` 역할의 RPC를 호출한다. 다음 동작을 확인한다.

- 비인증 조회 허용, 비인증·위조 쿠키의 변경 요청 차단, 다른 출처의 POST 차단, 역할별 필드·기도부탁·비밀번호 권한 검사.
- 비밀번호 해시 저장, 세션 만료·로그아웃·비밀번호 변경에 따른 인증 해제, 로그인 횟수 제한.
- 숫자 `0`, 불리언 `false`, 쉼표가 들어간 본문 보존, 선택지 직렬화 및 잘못된 입력 거부.
- 필드 UUID 기반 데이터 연결, 이름 변경 후 기존 값 유지, 사용 중인 필드·선택지 변경 차단.
- 오래된 필드 구성과 기도부탁 수정 시각을 사용한 저장 거부.
- 27개 데이터의 목록 페이지 조회, 다중 선택 그룹의 중복 제거, 미입력 그룹, 숫자 정렬.
- 여러 필드의 AND·선택지의 OR 필터, 숫자·날짜 범위와 `0`·`false` 검색, SQL 삽입 문자열 처리.
- 비활성화한 그룹화·필터링 기준의 직접 API 요청 거부.
- 파일 UUID 반환, 미확정 파일의 업로드 세션 소유권, 저장 후 비인증 조회, 다른 기도부탁에서 파일 재사용 거부.
- 파일 삭제 실패 후 정리 큐 재시도, 위장·손상 파일 거부, 업로드 후 필드가 파일에서 이미지로 바뀐 경우 PDF 저장 거부.
- 공개 DB 역할의 앱 테이블 권한 회수와 RLS 활성화.

동시 수정 테스트는 오래된 버전의 저장 거부를 검증한다. 여러 DB 연결이 동시에 잠금을 획득하는 부하·경합 테스트는 포함하지 않는다.

## 브라우저 확인 (2026-10-06)

프로덕션 Next.js 화면과 `scripts/preview.ts`의 임시 SQL/API 서버를 연결했다. 테스트 데이터와 파일은 메모리에만 저장했다.

- 관리자 로그인, 동적 작성 폼 저장, 상세 조회, 목록 갱신.
- 기도 분류별 그룹화, 그룹 펼치기, 필터 조합과 초기화.
- 관리자 필드 편집에서 그룹화·필터링 설정 해제 후 화면 반영.
- 구성원 상세 화면에 수정·삭제 버튼이 없고, 관리자 인증 모달에서 부관리자 인증 후 버튼이 표시됨.
- 부관리자 수정 폼과 저장 흐름.
- 모바일 너비 390px에서 가로 넘침 없음, 조회 조건 접기·펼치기, 목록·모달 표시.

## URL·publishable key 전환 검증 (2026-10-07)

- PostgREST의 `apikey` 헤더와 RPC 인자 계약, 공개 키를 JWT로 보내지 않는 것을 확인했다.
- `anon` 역할에서 직접 호출해도 세션 없는 변경·관리 권한 위조·잘못된 입력·임의 SQL 요청·비밀번호 테이블 조회·비공개 보조 함수 실행이 거부된다.
- SQL Editor 설치 스크립트를 빈 DB에서 실행하고 재실행해도 이력과 비밀번호가 보존된다. `.env.local` 우선순위와 비밀번호 특수문자 처리도 확인했다.
- DB 직접 접속용 `pg` 의존성, 연결 문자열, HMAC 서명 비밀키 의존성을 제거했다.

## 공개 조회·상단 참여 모달 검증 (2026-10-08)

- 인증 없이 필드·목록·상세·그룹별 목록·복합 필터·게시된 첨부파일을 조회할 수 있다.
- 비인증·위조·만료 세션의 작성·수정·삭제·필드 관리·비밀번호 변경·업로드는 API와 직접 RPC에서 차단된다. 미확정 파일은 소유 세션만 조회하며, 삭제한 게시물의 첨부는 공개 조회할 수 없다.
- Browser로 메모리 DB와 분리된 Next.js 프로덕션 서버를 사용해 첫 진입 목록, 상단 참여 모달의 세 역할 인증, 구성원 작성 버튼, 부관리자 수정·삭제 버튼, 관리자 필드·비밀번호 메뉴를 확인했다.
- 로그아웃 후에도 그룹화·필터 선택과 목록이 유지되고, 비로그인 상태에서 그룹을 펼쳐 상세 내용을 새로 조회했다.
- 너비 393px에서 목록·참여 모달을 시각 확인했으며, 관리자 메뉴를 포함해 가로 넘침이 없었다.
- 후속 마이그레이션은 RPC 버전(3)과 네 조회 작업의 인증 예외만 변경한다. 원래 마이그레이션과 변경 작업의 권한 검사는 유지한다. SQL Editor 설치 파일도 다시 생성했다.
- Supabase CLI 보안 advisors는 로컬 Supabase DB(54322)가 실행되지 않아 연결할 수 없었다. PGlite의 실제 SQL·역할·테이블 권한 검증은 통과했으며, 실제 Supabase 적용·advisors·S3 연결 검증은 남아 있다.

## 비밀번호 제한 제거·초기 등록 검증 (2026-10-08)

- 화면의 최소·최대 길이 속성, 로그인 API 최대 길이 검사, DB의 해시 생성·로그인 길이 검사, 초기 SQL 생성기의 길이·문자 검사를 제거했다. 공백을 자르거나 문자를 정규화하지 않는다.
- 실제 SQL과 API에서 한 글자, 128자를 넘는 한글 비밀번호, 공백·따옴표·특수문자를 포함한 값으로 변경·로그인했다. 끝 문자가 다른 비밀번호는 거부되며 기존 해시 저장과 시도 횟수 제한은 유지된다.
- `--schema-only` 적용 후 비밀번호가 0건임을 확인하고 `db:seed`에 해당하는 SQL로 세 역할을 등록했다. 반복 실행 시 기존 비밀번호가 보존되며 환경변수 누락은 명시적인 오류가 된다.
- 현재 `.env` 값은 변경하지 않고 `.local/supabase-passwords.sql`을 생성했다. 새 후속 마이그레이션을 먼저 적용한 뒤 초기 등록 SQL을 실행한다.
- 현재 Supabase 연결 도구의 SQL 실행 권한이 거부되어 실제 DB 조회·변경은 수행하지 못했다. SQL Editor에서 적용해야 한다.

## 실제 연결 후 남은 확인

1. `.env` 또는 `.env.local`의 Supabase URL·publishable key를 채우고, `db:prepare`로 만든 SQL을 SQL Editor에서 실행한다. `db:check`로 연결을 확인한다.
2. 실제 Supabase REST RPC 호출·테이블 직접 접근 차단, 여러 연결에서의 필드 변경·기도부탁 저장 경합을 확인한다.
3. 실제 S3 IAM·비공개 버킷에서 업로드·다운로드·교체·삭제 및 예약 정리 재시도를 확인한다.
4. 운영 HTTPS 도메인에서 Secure 쿠키·Origin 검증·역할별 전체 흐름을 확인한다. 모바일 실기기와 키보드 접근성도 최종 확인한다.

현재 구성원 인증은 **역할별 공유 비밀번호** 방식이다. 개인 계정·가입 승인·개인별 작성자 확인은 구현 범위에 포함하지 않는다. 실행 절차와 모든 환경변수는 [설정 안내](setup.md)를 참고한다.
