# 기능 1 개선 계획: 그리드 목록·필드 설정·집계·엑셀

작성일: 2026-10-08  
상태: 승인 후 구현·로컬 검증 완료 / 운영 DB 마이그레이션 적용 대기  
기준 문서: [변경 요청](../prompt/prompt_01.md), [기존 계획](plan1.md)

## 1. 목표와 적용 범위

기도부탁을 행과 열이 정렬된 그리드 목록으로 표시하고, 관리자가 필드 순서·선택지 색상·집계 여부를 설정할 수 있도록 확장한다. 목록의 조회 조건과 연결된 집계, 엑셀 다운로드·업로드를 추가한다.

이 문서에서 **확정 요구사항**은 요청 문서에 명시된 내용이다. 컬럼명, 엑셀 권한·처리 방식, 수량 제한 등 구체적인 구현 선택은 **설계 제안**이며 계획 검토 대상이다. 2026-10-08 사용자가 이 계획의 구현을 승인했고 아래 설계로 코드·마이그레이션·라이브러리를 반영했다. 실제 Supabase에는 SQL Editor 적용이 필요하다.

### 확정 요구사항과 대응 설계

| 번호 | 요구사항 | 반영 내용 |
| --- | --- | --- |
| 1 | 메인 목록을 그리드 리스트로 표시 | 기도부탁 한 건을 한 행, 필드를 열로 표시하는 표형 목록 |
| 2 | 리스트 행의 필드 노출 순서 설정 | 관리자 필드 순서 설정과 전체 목록의 공통 열 순서 |
| 3 | 기존 `글` 유형을 분리 | `짧은 텍스트` 추가, 기존 `글`과 데이터 유지 |
| 4 | 참고 사이트 기반 그룹화·필터 UI | 목록 상단 보기 선택·조건 영역, 그룹 접기·펼치기 |
| 5 | 엑셀 다운로드·업로드 | `.xlsx` 내보내기, 양식 다운로드, 검증·미리보기 후 가져오기 |
| 6 | 선택형 옵션별 색상 | 옵션별 색상 저장과 배지·강조색 적용 |
| 7 | 외부 color picker 사용 | 공통 색상 선택 컴포넌트에 외부 라이브러리 적용 |
| 8 | 필드의 집계 설정과 값별 행 수 UI | 관리자 집계 플래그, 전체·값별·그룹별 건수 |

### 유지할 기존 동작

- 첫 진입은 공개 조회이며, 인증은 상단 참여 모달에서 한다.
- `member`는 작성, `sub-admin`은 기도부탁 수정·삭제, `admin`은 모든 작업과 필드 설정을 수행한다.
- Supabase와 S3는 서버 전용 모듈을 통해 접근하고 공통 UI는 CSS Modules를 사용한다.
- `content`의 키는 필드 UUID다. 기존 `option`, `displaytype`, `listdisplaydata`와 다중 선택값의 쉼표 저장 규칙을 유지한다.
- 게시된 첨부파일의 공개 조회, 미확정 업로드의 세션 소유권, 비밀번호 해시·세션 검증을 유지한다.
- 비밀번호 길이·문자 조합 규칙을 다시 추가하지 않는다.

## 2. 참고 사이트에서 확인한 구성

[구리교회 기도부탁 참고 사이트](https://gurich-prayer.netlify.app/)를 2026-10-08에 브라우저로 확인했다. 아래는 실제로 확인한 UI와 이 프로젝트에 적용할 방향이다. 참고 사이트의 인명·실제 명단은 예제 데이터로 복사하지 않는다.

| 확인한 UI | 적용 방향 |
| --- | --- |
| 목록 위의 총합계와 색상별 상태 건수 카드 | 전체 결과 수와 집계가 켜진 필드의 값별 건수 |
| `전체보기`, `구역별`, `집회 참석현황` 보기 전환 | `전체보기`와 관리자가 허용한 필드별 그룹화 선택 |
| 공통 열 머리글을 가진 행 중심의 목록 | 동적 필드로 열을 구성하는 그리드 목록 |
| 그룹 이름, 총건수, 상태별 건수, 펼침 표시 | 그룹별 제목·건수·집계 요약과 접기·펼치기 |
| 목록 제목 옆 엑셀 작업 진입점 | `엑셀 다운로드`, 권한에 따른 `엑셀 업로드` 메뉴 |

참고 사이트의 보기 전환과 집계 배치를 참고하되, 구역·참석 상태 같은 특정 필드명을 고정하지 않는다. 복합 필터는 현재 앱의 타입별 조건을 목록 상단의 접이식 영역에 배치하는 설계 제안이다. 참고 사이트의 요일별 출석 관리는 이번 요청의 별도 기능으로 확장하지 않는다.

## 3. 메인 화면과 그리드 목록

### 3.1. 화면 배치

```text
교회 이름                                  참여하기 / 권한별 관리 메뉴
기도부탁 제목                              기도부탁 작성

현재 결과 총 N건
[집계 필드 A: 값별 색상 카드] [집계 필드 B: 값별 건수]

기도 목록                    엑셀 다운로드 / 업로드 / 양식 다운로드
[전체보기] [필드 A별] [필드 B별]             [필터 · 적용 수]
[접이식 필터 조건] [적용 중인 조건과 개별 해제]

필드 1       필드 2       필드 3 ...       작성일       상세
─────────────────────────────────────────────────────────
기도부탁 한 건의 값들
기도부탁 한 건의 값들
페이지 이동
```

**설계 제안:** `그리드 리스트`를 표형 목록으로 해석한다. 데스크톱에서는 공통 열 머리글과 행을 제공하고, 모바일도 같은 열 구조를 유지하되 목록 컨테이너 안에서 가로 스크롤한다. 페이지 전체의 가로 넘침은 막는다.

- HTML `table`을 기본으로 사용한다. 이번 기능만을 위해 대형 데이터 그리드 라이브러리를 도입하지 않는다.
- 한 행은 기도부탁 한 건이며, 동적 필드 열 뒤에 작성일과 상세 보기 버튼을 둔다.
- 긴 글은 줄바꿈과 최대 표시 높이를 적용하고 상세 모달에서 전체 내용을 보여준다. 원문은 자르지 않는다.
- 짧은 텍스트·숫자·날짜·선택형 값은 읽기 쉬운 최소 열 너비를 사용한다. 빈 값·숫자 `0`·불리언 `false`를 구분한다.
- 이미지·파일은 목록에서 첨부 표시 또는 작은 미리보기, 상세에서 기존 파일 조회 흐름을 사용한다.
- 그룹화한 목록에서도 같은 열 너비와 순서를 사용한다. 그룹 헤더에 이름·건수·집계 요약을 표시한다.
- 기존 상세 모달과 수정·삭제 권한을 재사용한다. 행 내부의 직접 편집은 이번 기본 범위에 추가하지 않는다.
- 페이지 단위 조회와 그룹 내부 페이지 조회를 유지한다. 그리드 전환 때문에 전체 데이터를 브라우저에 미리 적재하지 않는다.

### 3.2. 필드 순서와 `listdisplaydata`

**설계 제안:** 전체 열 순서는 필드의 `listOrder`로 관리한다. 필드 관리 화면에서 위·아래 이동 버튼으로 순서를 편집하고 한 번에 저장한다. 마우스 드래그는 필요할 때 추가하며, 키보드와 모바일에서도 같은 작업이 가능해야 한다.

- 그리드의 동적 열은 전체 필드 정의를 `listOrder` 순으로 구성한다. 같은 순서값의 보조 정렬은 생성 시각과 UUID로 고정한다.
- 기존 `listdisplaydata`는 행마다 **목록에 값을 표시할 필드의 집합**으로 유지한다. 선택하지 않은 필드의 셀은 비워 두고 전체 값은 상세에서 확인한다.
- 열 위치는 관리자 설정이 우선한다. `listdisplaydata` 안의 순서는 더 이상 행별 열 위치를 바꾸지 않는다.
- 작성 폼의 목록 표시 체크 기능은 유지한다. 모든 행이 동일한 머리글에 맞춰 표시되도록 한다.
- 관리자 순서는 필드 관리·작성·상세·엑셀의 기본 필드 순서에도 재사용한다.
- 순서 저장은 전체 UUID 목록과 `fieldRevision`을 검증하는 원자적 작업으로 처리한다. 중복·누락·알 수 없는 필드와 동시 편집 충돌을 거부한다.

이 항목은 기존 `plan1.md`의 “기도부탁별 선택 순서로 표시” 규칙을 변경한다. 기존 JSON 값과 표시 필드 선택은 보존한다.

## 4. 필드 모델과 입력 유형

### 4.1. `praycontentfield` 확장 제안

| 항목 | 저장 타입·기본값 | 용도 |
| --- | --- | --- |
| `listOrder` | integer, NOT NULL | 목록과 관련 화면의 필드 순서 |
| `optionColors` | jsonb, NOT NULL DEFAULT `'{}'` | 선택지 문자열 → `#RRGGBB` 색상 매핑 |
| `isAggregatable` | boolean, NOT NULL DEFAULT false | 값별 건수 집계 허용 |
| `datatype` | 기존 text 제약 확장 | `shorttext` 타입 추가 |

`option`은 쉼표 문자열로 유지한다. 색상은 배열 대신 매핑 객체이므로 별도 JSONB로 저장한다.

```json
{
  "option": "기도부탁,참석권유,참석가능,참석확정",
  "optionColors": {
    "기도부탁": "#8B5CF6",
    "참석권유": "#14B8A6",
    "참석가능": "#3B82F6",
    "참석확정": "#F59E0B"
  },
  "listOrder": 0,
  "isAggregatable": true
}
```

### 4.2. 짧은 텍스트와 글

| 화면 이름 | `datatype` 제안 | 입력 UI | 데이터 처리 |
| --- | --- | --- | --- |
| 짧은 텍스트 | `shorttext` | 한 줄 `Input` | 이름·관계·제목 등 간단한 문자열 |
| 글 | 기존 `string` 유지 | 여러 줄 `TextArea` | 긴 기도 내용과 줄바꿈 보존 |

- 기존 `string` 필드를 자동 변환하지 않는다. 저장된 기도 내용과 필드 UUID를 그대로 유지한다.
- 두 유형은 같은 문자열 저장 형식과 기존 10,000자 상한을 공유하는 것을 제안한다. 짧은 텍스트는 한 줄 입력 용도로 구분하며 별도의 짧은 길이 제한은 먼저 도입하지 않는다.
- `string` → `shorttext` 전환 시 기존 값에 줄바꿈이 있으면 전환을 거부하고 해당 내용을 먼저 정리하도록 안내한다. 자동 줄바꿈 제거·잘라내기를 하지 않는다. 반대 방향은 문자열을 그대로 보존할 수 있을 때 허용한다.
- 기존 “사용 중인 필드의 타입 변경 차단” 규칙에서 이 두 문자열 타입의 호환 전환만 별도로 검증한다.
- 입력 검증, 목록·상세 표시, 필터, 그룹화, 집계, 엑셀 변환까지 새 타입을 함께 지원한다.

### 4.3. 선택지별 색상과 color picker

- `selectbox`, `selectmultibox`에 옵션별 색상을 설정한다. 같은 선택지 구조를 쓰는 `checkbox`에도 적용하는 것을 제안한다. 요청의 `multibox`는 현재 코드의 `selectmultibox`에 대응한다.
- 기존 한 줄씩 입력하는 선택지 편집을 `옵션명 + 색상 + 제거` 행으로 바꾼다. 선택지 추가·정렬과 실제 배지 미리보기를 제공한다.
- 외부 라이브러리는 **`react-colorful`**을 우선 제안한다. `HexColorPicker`와 색상 코드 입력을 공통 `ColorPicker`로 감싸서 필드 관리에서 사용한다. [공식 사용 예제](https://github.com/omgovich/react-colorful#readme)
- 색상은 `#RRGGBB` 형식으로 정규화한다. 등록되지 않은 선택지 키와 임의 CSS 문자열은 서버와 DB에서도 거부한다.
- 색상을 설정하지 않은 옵션은 기존 테마색을 사용한다. 초기 마이그레이션에서 임의 색상을 일괄 배정하지 않는다.
- `badge`는 옵션색을 바탕으로 한 배지, `color`는 옵션 강조색, `bold`는 굵기로 조합한다. 배경과 글자색은 대비를 확보하고 색상만으로 값을 구분하지 않는다.
- 다중 선택은 각 옵션을 따로 렌더링한다. 여러 값을 하나의 문자열·하나의 배지로 합쳐 색상을 잃지 않도록 한다.
- 목록·상세·그룹 제목·집계 카드에서 동일한 색상 결정 함수를 사용한다.
- 사용 중인 선택지의 삭제·이름 변경은 기존 보호 규칙을 유지한다. 색상 변경만으로 데이터 값은 바뀌지 않는다.

## 5. 그룹화·필터·집계

### 5.1. 그룹화와 필터 조작

- `전체보기`와 `isGroupable=true`인 필드 버튼을 목록 상단에 배치한다. 필드가 많으면 가로 스크롤 또는 더보기 선택을 제공한다.
- 한 번에 하나의 필드로 그룹화한다. 그룹 이름과 건수를 누르면 그룹 내 그리드가 펼쳐진다.
- 필터는 `isFilterable=true`인 필드만 제공하며, 조건을 편집한 후 적용한다. 모바일에서는 접이식 영역으로 표시한다.
- 서로 다른 필드 조건은 AND, 같은 선택형 필드에서 여러 값을 고르면 OR로 결합하는 기존 규칙을 유지한다.
- 활성 조건을 태그로 표시하고 개별 해제·전체 초기화를 제공한다. `전체보기`는 그룹화만 해제하며 필터 초기화와 구분한다.
- 필터·그룹 기준 변경 시 페이지를 초기화한다. 관리자 설정이 바뀌어 유효하지 않은 조건은 해제하고 안내한다.

### 5.2. 집계 의미와 표시

필드 편집에 `목록에서 값별 건수 집계`를 추가한다. `isGroupable`, `isFilterable`, `isAggregatable`은 서로 독립적으로 설정한다.

**설계 제안:** 집계는 수치의 합·평균이 아니라 **해당 값을 가진 기도부탁 행 수**다. 목록의 현재 필터를 적용한 전체 결과를 대상으로 계산하며, 현재 페이지나 펼쳐진 그룹만 세지 않는다.

| 필드 타입 | 값별 집계 기준 |
| --- | --- |
| 하나 선택 | 옵션별 기도부탁 수, 등록 옵션은 0건도 표시 |
| 여러 개 선택·체크박스 그룹 | 선택된 각 옵션별 수, 같은 행·같은 옵션 중복은 1건 |
| 짧은 텍스트·글 | 기존 그룹화와 같이 앞뒤 공백을 정리한 전체 값별 수 |
| 숫자·날짜 | 숫자 값 또는 날짜 값별 수 |
| 예 / 아니오 | `true`, `false`, 미입력 구분 |
| 이미지·파일 | 첨부 있음·첨부 없음 |

- 전체 결과 수는 기도부탁 UUID로 중복 제거한다. 다중 선택의 옵션별 합계는 전체 건수보다 클 수 있음을 표시한다.
- 키 누락·null·빈 문자열은 미입력이다. `0`과 `false`는 정상 값이다.
- 목록 위에 전체 건수와 집계 필드별 값·건수를 표시한다. 여러 집계 필드는 제목으로 구분하고 필드 순서를 따른다.
- 그룹 헤더에도 해당 그룹 안의 전체 건수와 집계 필드별 요약을 제공한다. 그룹 안의 페이지 이동은 집계에 영향을 주지 않는다.
- 값이 많은 텍스트·숫자 필드는 상위 항목과 더보기로 나누어 표시한다. 숨겨진 값 때문에 전체 건수가 잘못 보이지 않도록 표시 범위를 안내한다.
- 집계 카드를 눌러 필터를 적용하는 동작은 해당 필드가 필터링도 허용할 때만 제공한다. 집계 전용 필드는 조회용으로 표시한다.

### 5.3. 서버 계산

- 기존 필터 조건 해석을 목록·그룹·집계·엑셀 조회에서 공유한다.
- 목록 결과와 전체 집계는 가능한 한 동일 RPC·동일 DB 스냅샷으로 계산한다. 그룹별 요약도 전체 필터 집합에서 해당 그룹을 대상으로 계산한다.
- 클라이언트가 임의의 비허용 필드로 집계하거나 필터링하지 못하도록 DB에서 플래그와 타입을 재검증한다.
- 필드 설정·기도부탁 저장·삭제·엑셀 반영 후 목록과 집계를 함께 갱신한다. 오래된 요청의 응답이 최신 조건을 덮어쓰지 않게 한다.
- 집계가 꺼진 필드의 상세 집계는 계산하지 않는다. 고유값이 많은 필드는 결과 개수 제한·페이지 조회를 설계하고 실제 쿼리로 성능을 확인한다.

## 6. 엑셀 다운로드·업로드

### 6.1. 범위와 공통 처리

**설계 제안:** 1차 지원 형식은 `.xlsx`다. 파싱과 생성은 서버 전용 `lib/server/excel` 모듈에 둔다. 후보는 XLSX 읽기·쓰기와 서식 처리를 지원하는 **ExcelJS**이며, 구현 시 Node·라이선스·의존성 검증 후 버전을 고정한다. [공식 문서](https://github.com/exceljs/exceljs#readme)

S3 첨부 업로드와 엑셀 데이터 가져오기는 별도 API로 구분한다. 엑셀은 기도부탁 데이터를 해석하기 위한 입력이며, 원본 파일을 자동으로 공개 첨부파일에 등록하지 않는다.

### 6.2. 다운로드

- 기본 다운로드는 **현재 필터에 맞는 전체 결과**다. 화면 한 페이지에만 한정하지 않는다. 전체 목록 다운로드는 필터를 해제해 선택한다.
- 그룹화로 여러 그룹에 속하는 기도부탁도 데이터 시트에는 UUID당 한 행만 내보낸다. 그룹·집계 정보는 별도 요약 시트로 제공한다.
- 데이터는 화면에서 줄임 표시한 내용이 아닌 원문을 사용한다. 상세에서 공개하는 모든 필드를 포함하고 열은 `listOrder`를 따른다. 다운로드 메뉴에 이 범위를 표시한다.
- 머리글은 필드 이름, 안정적인 연결은 숨김 메타데이터의 필드 UUID를 사용한다. 기도부탁 UUID·수정 버전·행별 `listdisplaydata`도 시스템 메타데이터로 보존한다.
- 메타데이터는 연결 편의를 위한 정보이며 권한 증거로 신뢰하지 않는다. 업로드 시 현재 DB 정의와 다시 대조한다.
- 셀 타입을 명확히 지정해 숫자·불리언·날짜와 문자열의 앞자리 0·줄바꿈을 보존한다. 사용자 문자열을 Excel 수식으로 만들지 않는다.
- 파일·이미지는 앱의 공개 파일 조회 경로와 첨부 표시만 내보낸다. S3 경로나 비밀키를 포함하거나 파일 바이너리를 통합문서에 넣지 않는다.
- 서버에서 조회 조건을 한 번 확정한 결과로 만든다. 건수가 큰 경우의 상한과 스트리밍 처리를 정하고, 제한 초과 시 일부 행만 조용히 내보내지 않는다.

### 6.3. 업로드 흐름

1. 빈 엑셀 양식을 받거나 다운로드한 파일을 준비한다.
2. 파일과 작업 모드를 선택한다. 기본 모드는 `새 기도부탁 추가`, 관리 권한에는 `기존 기도부탁 수정`을 별도로 제공한다.
3. 서버에서 파일 형식·셀 타입·필드 정의·선택지·권한을 검사한다. 필드 UUID 메타데이터가 없으면 열 이름 매핑을 미리보기에서 확인한다.
4. 신규·수정·오류 건수와 행별 변환 결과를 보여준다. 오류는 엑셀 행 번호·필드 이름·수정 방법으로 표시한다.
5. 사용자가 반영을 누르면 서버가 현재 권한, 최신 필드 정의와 수정 버전을 다시 검증한다.
6. 검증된 한 업로드를 DB 트랜잭션으로 반영하고 목록·집계를 갱신한다. 한 행이라도 실패하면 해당 업로드 전체를 반영하지 않는다.

### 6.4. 데이터 보존·오류 처리 제안

- 추가 모드에서 기존 UUID가 있는 행은 오류로 표시한다. 다운로드 파일을 실수로 다시 올려 중복 생성하지 않게 한다.
- 수정 모드에서는 존재하는 UUID와 `updateDateTime`이 필요하다. 알 수 없는 UUID를 자동 생성으로 전환하거나 엑셀에 없는 DB 행을 삭제하지 않는다.
- 수정 시 매핑하지 않은 열은 보존한다. 매핑한 열의 빈 셀은 값 지우기로 해석하고 미리보기에서 명시한다. 신규 행의 빈 셀은 미입력으로 처리한다.
- 숫자는 유효 범위를 검증하고, 날짜는 달력 날짜로 정규화한다. 예/아니오와 다중 선택값의 허용 표현을 양식 안내에 적는다. 잘못된 선택지는 자동 추가하지 않는다.
- 문자열의 공백·줄바꿈·한글을 보존한다. 다중 선택만 기존 쉼표 분리·중복 제거 규칙을 따른다.
- 이미지·파일 필드는 엑셀로 생성·교체하지 않는다. 신규 행에서는 비워 두고, 수정 행에서는 기존 첨부를 그대로 보존한다. 외부 URL이나 다른 행의 파일 UUID를 받아 연결하지 않는다.
- 수식 셀은 계산하지 않고 오류로 안내한다. 매크로·외부 참조·지원하지 않는 병합 구조는 명시적으로 거부한다.
- 초기 한도 제안은 파일 5MB, 데이터 500행, 필드 40개다. 압축 해제 크기·셀 수·처리 시간도 제한한다. DB에 보내는 정규화 JSON은 기존 RPC의 512KiB 상한을 지키고, 초과 시 파일을 나누도록 안내한다.
- 미리보기 데이터를 브라우저가 조작할 수 있다고 보고 확정 단계에서도 전체 검증한다. 세션에 연결된 작업 ID로 재시도 중복 반영을 방지한다.
- 대량 저장은 기존 단건 저장을 무작정 반복하지 않는다. 공통 검증·저장 규칙을 재사용하는 일괄 RPC를 만들고, 별도 요청·행 수 제한을 DB에서 적용한다. 새 경로가 작성 횟수 제한을 우회하지 않게 한다.

### 6.5. 엑셀 권한 제안

| 작업 | 비인증 방문자 | member | sub-admin | admin |
| --- | --- | --- | --- | --- |
| 공개 데이터 엑셀 다운로드 | 허용 | 허용 | 허용 | 허용 |
| 엑셀 양식 다운로드 | 허용 | 허용 | 허용 | 허용 |
| 엑셀 대량 추가·수정 | 불가 | 불가 | 허용 | 허용 |
| 엑셀로 필드·선택지 자동 생성 | 불가 | 불가 | 불가 | 이번 범위 미지원 |

대량 업로드를 운영 작업으로 보고 관리 역할에 제공하는 제안이다. 구성원의 일반 작성 권한은 유지한다. 업로드 권한은 원문에서 정하지 않았으므로 계획 검토 시 변경할 수 있다.

### 모듈별 책임

| 테스트·운영 문서 | 마이그레이션·권한·엑셀 왕복 검증과 설치 절차 |

### 마이그레이션 원칙

1. 기존 파일은 수정하지 않고 Supabase CLI로 후속 마이그레이션을 생성한다.
2. `listOrder`는 기존 생성 시각·UUID 순으로 채워 현재 순서를 보존한다. 새 필드는 마지막에 배치한다.
3. `optionColors={}`, `isAggregatable=false`로 시작한다. 관리자가 설정하기 전 집계·색상은 기존 화면과 호환된다.
4. `shorttext` 허용 제약과 관련 SQL 검증·필터·그룹 함수, 필드 JSON 응답을 함께 갱신한다. 기존 `string`과 `content`는 자동 재작성하지 않는다.
5. 순서·색상·집계 변경도 필드 수정 버전과 `fieldRevision`에 반영한다.
6. 엑셀 작업의 중복 방지 정보가 필요하면 비공개 스키마에 세션·작업 ID·상태·결과를 저장한다. 만료 정리도 포함한다.
7. 기존 RLS·비공개 함수 구조를 유지하고 공개 테이블 직접 접근 권한은 추가하지 않는다. 새로운 변경 RPC도 역할과 세션을 검증한다.
8. 로컬 이행·재실행·기존 데이터 보존을 검증한 뒤 SQL Editor 적용 파일과 확인 절차를 제공한다. 실제 DB 적용 여부를 로컬 검증과 구분해 기록한다.

## 8. 구현 순서

1. **필드 모델과 호환성**: 추가 컬럼·타입, 기존 데이터 이행, 서버·DB 검증, 공통 정렬·색상 규칙을 구현한다.
2. **필드 관리 UI**: 순서 이동, 옵션별 ColorPicker, 집계 체크, 짧은 텍스트 입력과 미리보기를 구현한다.
3. **목록 개편**: 그리드와 모바일 스크롤, 상단 그룹화·필터, 상세 모달 연결을 구현한다.
4. **집계**: 전체·필드값·그룹별 건수와 색상 카드, 조회 조건 변경·갱신을 연결한다.
5. **엑셀 다운로드**: 양식·전체 필터 결과·메타데이터·타입 보존을 구현한다.
6. **엑셀 업로드**: 권한·매핑·미리보기·오류 보고·트랜잭션·재시도 중복 방지를 구현한다.
7. **통합 검증**: 자동 검사와 데스크톱·모바일 실제 화면, 기존 기능 회귀를 확인하고 적용 문서를 정리한다.

## 9. 완료 기준

아래 체크는 구현과 로컬 SQL/API·브라우저 검증 기준이다. 실제 모바일 기기·Supabase 스키마 적용·S3 연결 및 브라우저 파일 전송 검증의 한계는 [검증 기록](../docs/verification.md)에 구분했다.

- [x] 목록의 한 행은 기도부탁 한 건이며 모든 행과 그룹에 같은 필드 순서가 적용된다.
- [x] 관리자 순서 변경 후 새로고침·다른 기기·엑셀에서도 순서가 유지되고 기존 표시 필드 선택은 보존된다.
- [x] 모바일의 긴 텍스트·많은 열에서도 페이지 전체가 가로로 넘치지 않으며 상세 원문을 확인할 수 있다.
- [x] 짧은 텍스트와 글을 생성·저장·조회하고 기존 긴 글을 손실 없이 유지한다.
- [x] 다중 선택의 각 옵션색과 배지·굵게·강조색 조합이 목록·상세·집계에서 일치한다.
- [x] 외부 ColorPicker로 색상을 고르고, 잘못된 색상·알 수 없는 옵션 키는 직접 RPC에서도 거부된다.
- [x] 그룹화·필터·집계 플래그가 독립적으로 적용되고 비허용 조건은 서버에서 거부된다.
- [x] 페이지를 넘겨도 집계 건수는 전체 필터 결과와 일치하며 다중 선택 중복·미입력·0·false를 올바르게 처리한다.
- [x] 다운로드에 현재 조건의 전체 결과가 포함되고 그룹 중복 행·원문 누락·수식 변환이 없다.
- [x] 엑셀의 짧은/긴 문자열·날짜·숫자·불리언·다중 선택을 왕복 변환해 검증한다.
- [x] 잘못된 행·중복 UUID·수정 충돌·변경된 필드·위조된 미리보기·첨부 참조를 저장 전에 검증한다.
- [x] 업로드 실패 시 부분 저장이 없고 같은 작업의 재시도로 중복 생성되지 않는다.
- [x] 비인증·member의 일괄 변경과 sub-admin의 필드 설정 변경을 API·직접 RPC 모두에서 차단한다.
- [x] 공개 조회·참여 모달·로그아웃·일반 CRUD·S3 첨부·비밀번호 변경이 회귀 없이 동작한다.
- [x] 마이그레이션 전후 기존 데이터와 세션을 검증하고 린트·타입 검사·테스트·빌드를 통과한다.
- [x] 로컬 자동 검사, 브라우저 확인, 실제 Supabase·S3 연결 검증을 구분해 기록한다.

## 10. 검토할 주요 설계 선택

| 항목 | 기본 제안 |
| --- | --- |
| 그리드 의미 | 행·열이 정렬된 표, 모바일은 목록 내부 가로 스크롤 |
| 필드 순서 | 관리자의 전역 순서 우선, 행별 `listdisplaydata`는 표시 여부 유지 |
| 짧은 텍스트 | 한 줄 입력을 추가하고 기존 글 데이터는 유지 |
| 집계 대상 | 현재 필터에 맞는 전체 데이터의 값별 행 수 |
| 엑셀 다운로드 | 공개 조회 권한과 동일, 현재 필터의 전체 원문 데이터 |
| 엑셀 업로드 | admin·sub-admin만, 추가/수정 모드 분리, 확정 전 미리보기 |
| 업로드 오류 | 업로드 단위 전체 성공 또는 전체 취소 |
| 라이브러리 | react-colorful, 서버용 ExcelJS를 우선 검토 |
